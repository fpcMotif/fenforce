## Useful commands

Run these commands from the repository root with `bunx vite-plus run twenty-server#{task}`.

### First time setup

```
bunx vite-plus run twenty-server#database:reset # setup the database with dev seeds
```

### Starting the server

```
bunx vite-plus run twenty-server#start
```

### Lint

```
bunx vite-plus run twenty-server#lint
bunx vite-plus run twenty-server#lint:fix # fix lint errors
```

### Test

```
bunx vite-plus run twenty-server#test             # run unit tests
bunx vite-plus run twenty-server#test:integration # run integration tests
```
Run `bunx vite-plus run twenty-server#test:integration:with-db-reset` when integration tests need a database reset.

### Resetting the database

If you want to reset and seed the database, you can run the following command:

```bash
bunx vite-plus run twenty-server#database:reset
```

### Migrations

#### For objects in Core/Metadata schemas (TypeORM)

```bash
bunx vite-plus run twenty-server#database:migrate:generate --name <name> --type <fast|slow>
```

## Tech Stack

Twenty primarily uses NestJS for the backend.

Prisma was the first ORM we used. But in order to allow users to create custom fields and custom objects, a lower-level made more sense as we need to have fine-grained control. The project now uses TypeORM.

Here's what the tech stack now looks like.


**Core**
- [NestJS](https://nestjs.com/)
- [TypeORM](https://typeorm.io/)
- [GraphQL Yoga](https://the-guild.dev/graphql/yoga-server)

**Database**
- [Postgres](https://www.postgresql.org/)

**Third-party integrations**
- [Sentry](https://sentry.io/welcome/) for tracking bugs

**Testing**
- [Jest](https://jestjs.io/)

**Tooling**
- [Bun](https://bun.com/)
- [Oxlint](https://oxc.rs/docs/guide/usage/linter.html)

**Development**
- [AWS EKS](https://aws.amazon.com/eks/)
