# Frontend feature and acceptance map

## At a glance

For M1, use the [Salesforce pilot contract](m1-contract.md) to select required journeys and applicable gates. This document retains the broader Twenty preservation scope; source presence does not establish company usage. Unselected items remain unverified, not implemented or implicitly excluded.

Frontend migration risks losing behavior because Twenty spreads capabilities across routes, settings, commands, and shared record components.
This map defines checks for Cloudflare hosting, TanStack Router, TanStack Query, and Convex.
Existing capabilities remain the baseline until each replacement passes the shared gates and its positive and negative checks.

## Coverage and remaining inventory

This pass followed route registration, navigation permissions, index dispatch, and representative implementations.
Those implementations covered mutation, import, export, search, settings, and layout entry points.
File listings identified supporting commands; their rows distinguish entry-point evidence from traced behavior.
No application startup, browser inspection, provider calls, or acceptance test runs established parity during this inventory.

This grouped map is not exhaustive.
Expand these areas before declaring frontend migration complete.

- Every field editor, clipboard action, drag interaction, filter operator, aggregate operation, and pagination boundary.
- Activity timelines, attachments, email threading and replies, message campaigns, and calendar interactions.
- Provider-side account sync, billing, authentication, marketplace installation, and AI tool execution.
- Admin panel queues, health, configuration variables, and AI provider management.
- Every workflow node configuration, activation command, retry command, stop command, and execution semantic.
- Accessibility, localization completeness, responsive rendering, keyboard navigation, and live feature enablement.

Each migrated row needs role-scoped fixtures and persisted output comparisons against the existing application.
Verify subscription cleanup, reconnect behavior, optimistic rollback, and concurrent surfaces through the shared acceptance gates.
Inspect actual desktop and mobile rendering before claiming visual or interaction parity.
